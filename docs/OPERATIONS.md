# 운영 연결과 배포

현재 서버 저장, 이메일 인증·비밀번호 복구·계정 삭제, 웹앱 설치 설정까지 구현했습니다. 외부 인터넷 배포와 실제 메일·푸시 발송은 운영 계정이 연결되지 않아 수행하지 않았습니다.

## 도메인이 준비되면

서버의 80/443 포트와 도메인 DNS를 연결한 후 `.env`에 다음을 설정합니다. 예시 값은 실제 운영 정보로 바꿔야 합니다.

```dotenv
APP_DOMAIN=your-real-domain.example
SUPPORT_EMAIL=your-support@example.com
MAIL_FROM=멍백홈 <noreply@your-real-domain.example>
RESEND_API_KEY=운영서버에만_설정
```

```sh
docker compose up -d --build
```

Compose는 API를 외부에 직접 노출하지 않고 Caddy를 통해 HTTPS로 제공합니다. DB와 푸시 키는 명명된 볼륨에 유지됩니다. 이미 운영 중인 볼륨을 초기화하거나 `down -v`로 삭제하지 마세요. 이 구성은 작성만 완료했으며 여기에서 Docker 배포를 실행하지 않았습니다.

배포 후 `node scripts/smoke-public.mjs https://실제도메인`으로 HTTPS 응답, 보안 세션 쿠키, 운영 모드, 예시 데이터 제외, manifest와 서비스 워커를 확인합니다. 이 명령은 테스트용 비회원 세션 하나를 생성하며 신고나 이메일은 작성·발송하지 않습니다.

Docker 없이 배포한다면 Node 24, `npm ci`, `npm run build` 후 환경 변수 `PUBLIC_ORIGIN`, `PUSH_SUBJECT`, `NODE_ENV=production`, `SEED_EXAMPLES=false`, `MAIL_FROM`, `RESEND_API_KEY`를 설정하고 `npm start`를 실행하세요. HTTPS 리버스 프록시가 앞에 있어야 Secure 세션 쿠키가 작동합니다. 직접 신뢰하는 프록시 한 대를 거칠 때만 `TRUST_PROXY=1`을 사용하세요. API 포트를 인터넷에 직접 개방하지 마세요.

`npm run check:production`은 키 값을 출력하지 않고 설정 누락을 확인합니다. Compose에서는 실행 환경에 위 값이 들어가므로 `docker compose exec app node scripts/check-production.mjs` 대신 로컬 또는 CI에서 검사를 실행하세요. Docker 이미지에는 운영에 필요한 server/dist만 포함합니다.

## 이메일과 계정

- Resend 어댑터를 구현했습니다. 발신 도메인의 소유권과 DNS(SPF/DKIM 등)를 Resend에서 확인한 후 인증된 발신 주소를 `MAIL_FROM`에 지정합니다. 외부 메일 발송 계정이 다르면 어댑터를 교체할 수 있습니다.
- 회원가입 시 인증 메일을 보내고, 내 계정에서 다시 받을 수 있습니다. 메일이 발송되지 않으면 계정은 남으며 재시도가 가능합니다. 설정이 없으면 발송 성공으로 표시하지 않습니다.
- 운영 모드에서는 이메일 인증을 완료해야 실종 신고를 등록·수정할 수 있습니다. 목격 제보는 비회원도 가능합니다.
- 인증 링크는 24시간, 비밀번호 재설정 링크는 30분 유효합니다. 서버에는 토큰 해시만 저장하며 링크를 쓴 뒤 재사용할 수 없습니다. 브라우저는 링크를 읽은 뒤 주소 표시줄에서 토큰을 제거합니다.
- 인증 또는 비밀번호 변경 시 기존 모든 세션·푸시 구독을 해제하고 관련 토큰을 폐기합니다. 다시 로그인하고 기기별 알림을 켜주세요.
- 비밀번호 복구 요청은 이메일 가입 여부를 동일한 응답으로 처리합니다. 메일 공급자 지연으로 가입 여부가 드러나지 않도록 발송을 응답과 분리합니다. 발송 실패 시 사용자가 재요청할 수 있으며 현재 메일 재시도 큐는 없습니다.
- 계정 삭제는 현재 비밀번호를 확인합니다. 운영 DB에서 본인 작성 기록·사진·대화 메시지·세션·구독을 제거합니다. 다른 사람이 작성한 목격은 유지하고 삭제된 신고와의 연결을 해제합니다. 별도 백업에 남은 데이터의 보관 기간과 삭제 절차는 운영 정책에 따라 설정해야 합니다.

구현 기준: [OWASP 비밀번호 복구](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html), [Resend 중복 발송 방지](https://resend.com/docs/dashboard/emails/idempotency-keys).

## 휴대폰 웹앱

일반 브라우저에서도 설치 없이 이용합니다. manifest, 192/512 아이콘, iOS 터치 아이콘, 홈 화면 추가 안내, 안전 영역, 키보드가 열린 화면 높이 대응을 추가했습니다. 연결이 끊긴 상태에서 다시 열면 오프라인 안내를 보여줍니다. 신고·사진·대화 API 데이터는 서비스 워커에 캐시하지 않습니다.

아이폰의 웹 푸시는 홈 화면에 추가한 웹앱에서 사용합니다. 해당 조건을 만족하지 않으면 설치 안내를 제공합니다. [WebKit 공식 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

내 계정 → ‘이 휴대폰에서 기능 확인’에서 위치 권한과 오차, 설치 상태를 보고 본인에게 테스트 푸시를 요청할 수 있습니다. 버튼을 누르는 사용자에게만 발송합니다. 확인 결과는 [실기기 검증표](DEVICE-QA.md)에 기록합니다.

## 알림

- 서비스가 열려 있으면 SSE로 새 상태를 받아 알림함과 지도를 갱신합니다.
- 백그라운드 알림은 서비스 워커, Push 구독, VAPID 발송을 사용합니다. 사용자가 직접 브라우저 알림을 켜야 합니다.
- `PUSH_SUBJECT`는 실제 연락 가능한 `mailto:` 또는 HTTPS URI로 설정합니다. 미설정 시 UI는 발신 설정이 필요하다고 알리고 실시간 알림함을 계속 제공합니다.
- 브라우저와 OS에 따라 지원 및 설치 요건이 다릅니다. iOS/Android 실기기에서 권한 허용·거절·재접속·백그라운드를 검증하세요.
- 큐는 DB에 저장하며 일시 실패 시 지수 간격으로 최대 6회 시도합니다. 만료된 404/410 구독은 제거합니다. 푸시가 실패해도 서버 알림함의 소식은 유지됩니다.
- 자동화에서는 발송기를 주입해 재시도를 검증합니다. 실제 외부 푸시 제공자로 테스트 알림을 발송한 것은 아닙니다.

## 운영자와 백업

먼저 웹에서 운영 계정을 만든 다음 서버에서 명시적으로 권한을 부여합니다.

```sh
node server/admin.mjs registered-admin@example.com
node server/backup.mjs
```

Docker 환경에서는 `docker compose exec app` 뒤에 같은 명령을 사용합니다. 백업은 SQLite backup API로 일관된 파일을 생성합니다. 백업을 별도 저장소에 보관하고 복원 검증과 보관 주기는 운영자가 설정해야 합니다.

## 공개 출시 전 남은 작업

- 도메인·서버·메일 계정 연결, 실제 메일 도착 확인, 백업 보관 기간 확정
- 실제 연락 수단과 신고 대응 담당자, 운영 시간
- 동시 사용자·대용량 사진·지역별 검색 부하에 대한 검증 및 필요 시 Postgres/PostGIS 전환
- 공공 보호 정보의 공식 API 발급·이용 조건 검토·동기화
- 운영에 적합한 지도 타일 제공자와 주소 검색 서비스 설정
- HTTPS 배포 후 실제 휴대폰 위치·방향·푸시·전단 QR 확인
- 장애 모니터링, 장기 감사 기록, 외부 알림 전달 지표

지도는 OpenStreetMap 공개 타일을 사용하며 위치/지도를 열면 외부 서버에 접속합니다. 개인정보 안내는 현재 구현을 설명하는 초안이며 실제 운영 주체·연락처·보관 정책 확정 후 공개해야 합니다.

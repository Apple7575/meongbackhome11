# 멍백홈 토스 원칙 재설계 — 1단계 설계

- 작성일: 2026-09-29
- 상태: 사용자 승인 (섹션 1~4 대화에서 승인), 문서 검토 대기
- 브랜치: `toss-redesign-phase1` (`worktree-mobile-ux`의 모바일 수정 위에서 시작)

## 0. 배경과 목표

모바일 실사용 화면이 산만하다(카드 모양 제각각, 장식 과다, 마이홈의 로그아웃이 알림 카드 안에 있음 등). 레퍼런스로 **토스**를 정하고, 토스가 공개한 제품 원칙 10개와 UX 라이팅 원칙 8개를 모두 적용한다.

### 결정 사항

| 항목 | 결정 |
|---|---|
| 겉모습 | 중간 — 기본은 무채색, 코랄은 화면당 주요 버튼 하나, 마스코트는 빈 화면·완료 화면에만 |
| 1단계 범위 | 공통 디자인 규칙 + 홈·찾기·목격 소식·마이홈(+설정) |
| 2단계 범위 (이 문서 밖) | 신고·제보 폼, 강아지 상세, 로그인·계정, 채팅, 알림함, 재회 이야기, 운영 화면, 팝업의 아래 시트화, 옛 CSS 삭제 |
| 데스크톱 | 모바일 화면을 가운데 480px 기둥으로 표시 |
| 구현 | React로 새로 작성, 점진 전환 (옮기지 않은 화면은 기존 코드 재사용) |

### 제약

- TDS UI 키트·`@toss/tds-mobile` 패키지는 앱인토스 전용 라이선스라 **사용 금지**. Toss Product Sans도 외부 사용 허가 없음 → **원칙과 공개 수치만 참고해 자체 규칙**을 만든다.
- 서버, API, DB, 배포 설정(Vercel·Docker·render), 서비스 워커·manifest는 변경하지 않는다.

## 1. 적용할 토스 원칙

출처: 제품 원칙 https://toss.im/tossfeed/article/tossproductprinciples · 라이팅 원칙 https://toss.tech/article/8-writing-principles-of-toss · 오류 문구 https://toss.tech/article/introducing-toss-error-message-system

### 제품 원칙 10개 → 1단계 적용

| 원칙 | 적용 |
|---|---|
| Casual Concept | 기술 용어 제거 ("브라우저 알림 켜기" → "새 목격 소식 알림 받기") |
| Simple Policy | 로그인은 등록 시점에만 (이미 적용됨). 둘러보기·목격 제보는 로그인 없이 |
| Value First | 홈 첫 화면에 실종견 목록. 알림 권한은 신고 등록 직후 맥락에서만 제안 |
| Clear Action | 화면마다 핵심 행동 하나를 하단 고정 버튼 또는 첫 목록 줄로 |
| Context Based | 신고한 보호자가 홈에 오면 "보리를 찾고 있어요 · 새 제보 N건"을 맨 위에 |
| Easy to Answer | 필터는 선택형 버튼(털 색·크기·착용물), 지역은 목록에서 고르기 |
| Explain Why | 주요 버튼 아래 한 줄 설명, 미인증 안내에 이유 표시 |
| One Thing | 화면 본문(`main`) 안의 코랄 진한 버튼 1개 이하. 하단 메뉴의 "+ 신고"는 모든 화면 공통 요소라 제외 |
| No More Loading | 불러오는 동안 목록 줄 모양 뼈대(Skeleton) 표시, 저장(하트)은 즉시 반영 |
| Minimum Features | 홈의 큰 그림·재회 배너·3단계 소개 제거, 전역 푸터 제거 → 설정으로 이동 |

### 라이팅 원칙 8개 → 모든 문구에 적용

해요체 · 다음 화면을 예측할 수 있는 버튼 문구 · 의미 없는 단어 삭제 · 제목을 되풀이하는 문장 삭제 · 지금 필요한 말만 · 말하듯 · 강요 대신 제안 · 누구나 아는 단어 · 숨은 감정(재회는 축하로).
오류 문구: "무슨 일 + 이유 + 다음에 할 일" 순서, 사용자를 탓하지 않음.

## 2. 공통 디자인 규칙 (`src/ui/tokens.css`)

### 색

- 회색 10단계: 50 `#F9FAFB` · 100 `#F2F4F6` · 200 `#E5E8EB` · 300 `#D1D6DB` · 400 `#B0B8C1` · 500 `#8B95A1` · 600 `#6B7684` · 700 `#4E5968` · 800 `#333D4B` · 900 `#191F28`
- 글자: 제목 900, 본문 700, 보조 500. 바탕 흰색, 구분 영역 50.
- 브랜드 코랄 `#E8805F` (진한 버튼 전용), 연한 코랄 `#FDF0EB` (배지·강조 배경).
- 상태 배지: 찾고 있어요 = 연한 코랄 바탕 + 코랄 글자, 집에 돌아왔어요 = 연한 초록 `#E8F7EE` + `#1E8E4E`, 예시 = 회색 100 + 회색 600.
- 제거: 베이지 배경, 점선 테두리, 반짝이 장식, 그림자 강조.

### 글자

- 글꼴: **Pretendard** (npm `pretendard` 패키지, 자체 제공), 대체 글꼴은 시스템 글꼴.
- 크기 7단계(px/행간): t1 30/40 · t2 26/35 · t3 22/31 · t4 20/29 · t5 17/25.5(본문) · t6 15/22.5 · t7 13/19.5.
- 13px 미만 금지. 단위는 `rem`으로 써서 폰의 글자 크기 설정을 따른다.
- 굵기: 400 / 500 / 600 / 700.

### 여백·모양

- 4px 단위. 화면 좌우 여백 20px. 목록 줄 세로 여백 12px(기본)·16px(사진 있는 줄).
- 둥글기: 버튼·입력창 12px, 사진 썸네일 12px, 아래 시트 윗모서리 20px.
- 카드 테두리 대신 목록 줄 + 구분선(회색 200, 1px) + 구역 사이 회색 50 띠(12px).
- 터치 영역 최소 44×44px.

| 부품 | 규격 |

### 전체 틀 (`App.jsx`)

- 상단 바: 홈은 로고, 나머지는 화면 이름 + 오른쪽 알림 종(`data-action="notifications"`). 마이홈은 오른쪽에 ⚙.
- 하단 메뉴 5칸: 홈 · 찾기 · + 신고(`data-action="report"`, 접근성 이름 "실종 신고") · 목격 소식 · 마이홈.
- 데스크톱(≥ 600px): 가운데 480px 기둥, 바깥은 회색 50 바탕. 하단 메뉴도 기둥 폭.
- 전역 푸터 없음. 서비스 안내·개인정보·운영 화면 링크는 설정으로.
- 연결 상태 배너(`#connection-banner`)는 상단 바 아래 유지.

## 3. 화면별 설계

### 홈 `#/`

1. 목록 줄 2개 (큰 버튼 역할)
   - "강아지를 잃어버렸어요" / 설명 "사진과 장소만 있으면 돼요" → `data-action="report"`
   - "강아지를 발견했어요" / 설명 "로그인 없이 알려줄 수 있어요" → `data-action="sighting"`
2. `ListHeader` "{지역}에서 찾고 있어요 {N}" + 지역 선택(아래 시트). 기본 지역은 사용자의 관심 지역 첫 번째, 없으면 "전국".
3. 찾는 중인 강아지 최대 5마리 `ListRow`(사진 56px, "이름 · 견종", "동네 · n시간 전", 배지). 누르면 `#/dog/{id}`.
4. "전체 보기" → `#/explore`.
5. 구역 띠 뒤 "집에 돌아온 아이들 {N}마리" 목록 줄 → `#/stories`.
- 신고한 보호자(`missing` 상태인 내 신고 존재): 1번 위에 "보리를 찾고 있어요" 블록 — 새 목격 제보 수, 마지막 목격 시각, `Button fill` "제보 확인하기" → `#/dog/{id}`. 이때 1번의 "잃어버렸어요" 줄은 숨긴다(코랄 버튼 1개 유지).
- 제거: 히어로 그림, 반짝이, 스티커, 재회 배너, "함께라면" 3단계, 예시 안내 띠(예시는 배지로 표시).

### 찾기 `#/explore`

- 상단 고정: 검색창 "이름, 견종, 동네로 찾기" (id `dog-search` 유지).
- 칩 줄: 지역▾ · 상태▾(전체/찾고 있어요/집에 돌아왔어요) · 필터(선택 개수 표시) · 지도 전환 아이콘.
- 필터 아래 시트: 털 색·크기·착용물 선택형 버튼 + "초기화" / "n마리 보기".
- 목록: `ListRow` 사진 72px, 20마리씩, 목록 끝에 "더 보기" 버튼(무한 스크롤 대신 명시적 버튼).
- 지도 보기: 전체 화면 지도(`maps.js` 재사용) + 아래 시트에 목록(접힘/펼침 2단계).
- 결과 없음: `EmptyState` "조건에 맞는 강아지가 없어요" + "필터 초기화".

### 목격 소식 `#/sightings`

- `Top` "목격 소식" + 지역▾.
- 날짜 묶음 `ListHeader`: 오늘 / 어제 / 이번 주 / 이전.
- `ListRow`: 위치 아이콘, 제목 "장소", 설명 "n분 전 · {방향}으로 이동 | 머물러 있었어요", 오른쪽 연결된 강아지 이름 배지(있을 때). 누르면 `data-action="report-detail"`(기존 창).
- 20개씩 + "더 보기".
- `BottomCTA` "강아지를 봤어요" → `data-action="sighting"`.

### 마이홈 `#/my`

- 상단 바 오른쪽 ⚙ → `#/my/settings`.
- 비로그인: `EmptyState`(마스코트) "로그인하면 내 신고와 제보를 한곳에서 볼 수 있어요" + `Button fill` "로그인" (`data-action="account"`).
- 로그인: 
  1. 프로필 줄: 닉네임(t3), 이메일 · 인증 상태 배지.
  2. 미인증이면 안내 줄 "이메일 인증을 마쳐야 신고를 등록할 수 있어요" + `Button weak sm` "메일 다시 받기"(`data-action="verify-resend"`).
  3. "내 신고": 내 신고 `ListRow`(사진, 상태 배지, 오른쪽 "새 제보 n"), 누르면 상세. 없으면 한 줄 "등록한 신고가 없어요".
  4. "우리 집 강아지": 프로필 `ListRow` + 마지막 줄 "＋ 강아지 등록하기"(`data-action="profile"`). 프로필 줄에서 "이 정보로 신고"는 오른쪽 텍스트 버튼(`data-action="report" data-profile`).
  5. "저장한 소식 {N}" 목록 줄 → 저장한 강아지 목록(같은 화면 안 펼침).
- 제거: "우리 아이와 함께하는 공간" 소개 문구, 알림 카드, 중복 버튼.

### 설정 `#/my/settings`

목록 줄만으로 구성: 새 목격 소식 알림 받기(`push`) · 관심 지역(`areas`) · 이 휴대폰에서 기능 확인(`data-action="account"` → 기존 계정 창이 열리고, 그 안의 "이 휴대폰에서 기능 확인" 버튼 사용. 2단계에서 별도 화면으로 분리) · 서비스 안내(`about`) · 개인정보 안내(`privacy`) · 운영 화면(`#/admin`) · 구역 띠 · 로그아웃(`logout`) · 계정 삭제(`delete-account`, 회색 600 글자).

### 알림 권한 제안

마이홈 첫 화면에서 요청하지 않는다. 신고 등록 성공 직후(기존 `registeredNext`)에 "보리 목격 제보를 바로 받으려면 알림을 켜주세요"를 제안(거절 가능).

## 4. 기술 구조

### 의존성

- 추가: `react@19`, `react-dom@19`, `@vitejs/plugin-react`, `pretendard`. 그 외 라이브러리 추가 없음(라우터·상태관리 라이브러리 없음).
- 언어: JavaScript + JSX. 스타일: CSS Modules(`*.module.css`) + `tokens.css`.
- 예상 번들 증가: gzip 약 60KB.

### 파일

```
src/app/main.jsx      React 시작점, 기존 main.js 초기화 호출
src/app/App.jsx       상단 바·하단 메뉴·화면 이동·레거시 영역
src/app/router.js     useRoute(): hashchange 구독, navigate(path)
src/app/useStore.js   useStore(): useSyncExternalStore로 client-store 구독
src/app/legacy.js     renderLegacy(el, route), 레거시 초기화 export
src/ui/*              공통 부품 + tokens.css
src/screens/Home.jsx Explore.jsx Sightings.jsx My.jsx Settings.jsx
```

### 기존 코드 연결

1. **데이터**: `client-store.js` 유지. `useStore`는 window 이벤트 `store-updated`, `connection-change`, `legacy-render`(새로 추가) 세 가지를 구독하고, 이벤트마다 버전 숫자를 올려 다시 그린 뒤 `read()`를 돌려준다. `remote-change`는 기존 `main.js`가 `refresh()`로 처리하고, 그 결과 `store-updated`가 발생하므로 직접 구독하지 않는다.
2. **동작**: React 버튼은 기존 `data-action`/`data-id`를 그대로 사용 → `main.js`의 문서 클릭 처리기가 폼·팝업을 연다. 화면 전용 상태(검색어·필터·지역·보기 방식)는 React가 소유한다.
3. **레거시 화면**: `/dog/*`, `/stories`, `/admin`, `/account/*`는 `App`이 `<div id="legacy-root">`를 두고 `renderLegacy(el, route)` 호출. `main.js` 변경점:
   - `render()`는 헤더·푸터를 그리지 않고 레거시 경로일 때만 `#legacy-root`에 그린다.
   - `render()` 호출 시 항상 `legacy-render` 이벤트를 보내 React도 갱신.
   - 1단계로 옮긴 화면의 함수(`hero`, `explorer`, `sightings`, `myHome`, `dashboard`, `footer`, `header`)는 7단계에서 삭제.
4. **팝업**: 기존 `#modal-root`·`openModal` 유지.
5. **스타일 격리**: 새 부품은 CSS Modules. React 틀 최상위(`.app`)에서 기존 전역 요소 규칙(button, h1~h3, a 등)의 영향을 초기화. 기존 `style.css`·`quality.css`는 2단계 끝에 삭제.
6. **지도**: `maps.js`의 `baseMap`/`marker`를 `useEffect` 안에서 호출, 언마운트 시 `map.remove()`.

## 5. 오류·빈 상태·로딩

- 연결 끊김: 기존 연결 배너 유지. 목록은 마지막 데이터 표시.
- 불러오는 중(`connection === "loading"`): `Skeleton` 5줄.
- 빈 목록: `EmptyState`(화면별 문구는 3장 참고).
- 오류 문구: "무슨 일 + 이유 + 다음에 할 일", 해요체.

## 6. 테스트

- `npm test`(서버·로직 26개): 변경 없이 매 단계 통과.
- Playwright: 클래스 기반 선택자(`.account-button`, `.dog-card`, `.hero-dogs`, `.owner-dashboard`, `.returning-hero` 등)를 역할·문구 기반으로 교체. 기능 범위(가입, 3단계 신고, 로그인 없이 작성 후 등록 시 로그인, 두 브라우저 실시간 알림·대화·재회, 목격 제보 임시 저장, QR 전단, 이메일 인증·비밀번호 복구, 오프라인·manifest) 유지.
- 새 자동 검사 (`tests/design-rules.spec.js`, 모바일·데스크톱):
  - 4개 탭과 설정의 `main` 안에서 코랄 fill 버튼 ≤ 1 (하단 메뉴 제외)
  - 보이는 모든 버튼·링크·입력 44×44px 이상
  - 320/360/430px에서 가로 넘침 없음
  - 보이는 글자 13px 이상
  - 마이홈 첫 화면에 로그아웃 없음, 설정에 있음
  - 레거시 경로(`/dog/demo-bori`, `/stories`, `/account/forgot`)가 React 틀 안에서 렌더됨
  - 데스크톱에서 본문 기둥 폭 480px
- 단계별 390px 캡처를 `artifacts/redesign/`에 저장해 사용자 확인.

## 7. 작업 순서

각 단계는 `npm test`, `npm run build`, `npm run test:browser` 통과 후 커밋.

1. React 틀 도입 — 모든 화면을 레거시가 그림, 겉모습 변화 없음.
2. 토큰·부품·Pretendard 추가.
3. 마이홈 + 설정 → **캡처 공유, 사용자 확인 후 진행.**
4. 홈.
5. 찾기(지도 포함).
6. 목격 소식.
7. 옮긴 화면의 레거시 함수·CSS 제거, 테스트 선택자 교체 마무리, 최종 캡처, 폰 확인 체크리스트 작성.

## 8. 배포

원격 저장소·Vercel CLI가 없어 사용자가 배포한다: 미리보기 배포 → 폰 확인 → 운영 배포. 문제 시 Vercel 이전 배포로 되돌리기.
